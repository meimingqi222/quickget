# QuickGet 功能缺失对比分析报告

> 说明：本报告分析的对象是 **当前仓库中的 QuickGet**（`/project`）——一个用 **Rust + GPUI** 开发的**原生多连接下载管理器**（Rust + GPUI，无 WebView，无 Electron）。
> 之前会话曾误将其当作 quickemu 项目里那个"下载 ISO 生成 VM 配置"的 `quickget` 工具，本报告已更正。

---

## 一、项目定位

QuickGet 是一个通用文件下载管理器，核心设计哲学是"粘贴任意标准链接，多连接分段拉取，保存到下载目录"——不是浏览器，也不是影音套件。

- **语言/框架**：Rust，GPUI 0.2（自定义渲染引擎，Material 浅色 UI，无 Electron/WebView 依赖）
- **协议**：HTTP / HTTPS / FTP / HLS(m3u8) / BitTorrent（librqbit）
- **平台**：macOS / Windows / Linux（macOS 打包用 `cargo-bundle`，单实例锁）
- **技术栈**：`reqwest`（rustls，HTTP/1.1 多连接）、`librqbit`（BT）、`suppaftp`（FTP）、`chrono`/`serde`/`uuid`
- **CLI**：`quickget <url> --dir <path> --connections N`，无界面下载
- **扩展**：Chromium Native Messaging 宿主（固定扩展 ID `agkijomhcpkgagodkkjknfnocfnalmcc`），右键投递链接与浏览器 Cookie

## 二、现有功能清单

### 2.1 下载核心

| 协议 | 功能细节 |
|---|---|
| **HTTP/HTTPS** | 多连接 Range 下载；默认 16 连接、小文件自动降连接数；探测用 `Range: bytes=0-1`（避开部分 nginx 的 `0-0→404` 坑）；自动跟随重定向（上限 16 次）；从 `Content-Disposition` 取真文件名并清洗；不接 gzip（`Accept-Encoding: identity`） |
| **断点续传** | `.part` 临时文件 + 侧车 `.qg.json`（含各分片偏移）；恢复时智能回读已下载数据，头部全零/空洞会回退重试；zip 文件额外做 EOCD 完整性检查 |
| **FTP** | 单连接，匿名或账号登录，`REST` 续传，二进制模式 |
| **HLS (m3u8)** | 解析播放列表、选取最高码率变体、并行拉分片、按序拼接为 `.ts`；**明确拒绝 AES 加密播放列表**（提示"暂不支持加密 HLS"） |
| **BitTorrent** | librqbit；magnet 链接与 `.torrent` 文件（HTTP 链接/本地路径）；DHT、公共 tracker 兜底（opentrackr/eu.org/moeking）、TCP+uTP 入站、UPnP 端口转发；种子标题重命名；每个任务独立目录，删除任务时整目录移回收织站 |

### 2.2 任务管理

- 队列：同时下载数默认 **3**，可设 1~16；其余排队
- 剪贴板监听：复制 URL 后弹窗询问是否加入队列
- UI 操作（任务列表）：暂停 / 恢复 / 重试 / 删除 / 打开文件 / 在文件夹中显示 / 展开文件详情
- 批量操作：暂停全部 / 恢复全部 / 清除已完成
- 视图过滤：全部 / 进行中 / 已完成 / 失败

### 2.3 网盘支持

- **百度网盘**：分享链接 → 直链解析。链路为"登录态转存到网盘 `/QuickGet/.tmp` → PCS `method=download` 换 302 真实直链 → 安卓客户端 UA 下载（4MB 单片限速防 31326 风控）"。
- 可选 `baidu-reverse` Cargo feature 启用**逆向增强**：本地 DES-ECB 解密百度分享 `sharedownload` 的加密 list，不走转存直接拿 dlink（逆向代码在私有子模块 `vendor/private-src/`，公开仓库不交付）。

### 2.4 扩展能力

- Chromium 扩展：右键链接投递 + 携带登录 Cookie；工具栏按钮下载当前页；**可开启"接管浏览器下载"**（默认关闭，`chrome.storage.local` 的 `intercept` 开关）；网盘分享页注入"QuickGet 下载"悬浮按钮。

### 2.5 设置项（Settings）

仅 5 项：**语言**、**保存目录**、**单任务连接数**（1~64）、**最大并发**（1~8）、**剪贴板监听开关**。

## 三、可比同类软件及其功能边界

| 软件 | 定位 | 典型能力 |
|---|---|---|
| **IDM**（Internet Download Manager） | Windows 下载器事实标准 | HTTP/FTP 多连接、**视频嗅探**、**下载规则**（按 URL 模式自动归类）、**计划任务**、**限速**、**代理**、浏览器深度集成、下载日志、ActiveX API |
| **Free Download Manager**（FDM） | 跨平台免费 | HTTP/FTP/BT、限速、**计划任务**、队列、浏览器集成、BT 做种、日志 |
| **Motrix** | 开源跨平台下载器 | HTTP/FTP/BT/magnet、限速、**代理**、**下载规则**、界面简洁 |
| **JDownloader 2** | 功能最全面的下载器 | 支持几乎全部网站（含验证码破解）、**网盘支持最广**、**下载规则**、**脚本/插件扩展**、**API**、批量 Linkgrabber、RSS、云脱壳 |
| **aria2** | 命令行/RPC 下载标杆 | HTTP/FTP/SFTP/BT/magnet、**RPC**、**代理**、**下载规则**、**限速**、**校验**、队列 |
| **Xtreamer** | 免费轻量级 | HTTP/FTP/BT、**视频嗅探**、**规则**、**计划任务**、**限速**、**代理** |
| **uGet** | Linux 开源下载器 | HTTP/FTP/BT、浏览器集成、**规则/分类**、插件 |
| **迅雷** | 国内 P2SP 下载器 | P2SP 加速、**网盘**、视频缓存、远程下载 |

**QuickGet 的相对位置**：它在"轻量、跨平台、多连接 + BT"这个区间与 FDM/Motrix 对标，网盘单点能力（百度）接近部分国内工具的入门水平，但**规则/计划/限速/代理/RPC/嗅探**这些中层功能普遍缺失，离 JDownloader 这类全功能下载器差距更大。

## 四、缺失功能分析（按优先级）

以下每一项均基于对 `src/` 源码的逐项排查（grep / 通读）确认，非凭空推测。

### 4.1 P0 级 —— 下载管理器"入门必备"，缺失即明显低一个档次

| 缺失功能 | 现状 | 同类标配 |
|---|---|---|
| **下载限速** | `settings.json` 无速率字段；引擎无任何速率限制逻辑 | IDM/FDM/Xtreamer/Motrix/aria2 均可设全局/单任务上限，避免占满带宽 |
| **代理支持** | 全项目**无任何**代理配置代码；`reqwest` 虽带 `socks` feature 但未暴露给用户 | aria2/IDM/Xtreamer/Motrix 均支持全局 HTTP/SOCKS 代理，可按域名分流 |
| **下载规则/分类** | 无 URL 模式/文件后缀规则；无法按站点自动归类到不同目录、自动命名 | IDM/FDM/Xtreamer/uGet/aria2 均有规则引擎（如 `*.zip → Downloads/Installers/`） |
| **计划任务** | 无定时/延时下载、无截止时间、无到期清理 | FDM/Xtreamer/aria2 支持设定下载时段、限速时段、过期删除 |

### 4.2 P1 级 —— 明显短板，影响核心使用场景

| 缺失功能 | 现状 | 同类标配 |
|---|---|---|
| **网盘支持单一** | 仅百度网盘；`providers/mod.rs` 的 `PROVIDERS` 注册表只有 `baidu` 一个 | JDownloader/迅雷/国内工具均支持**阿里云盘、夸克网盘、123 网盘、蓝奏云**，国际工具支持 **Google Drive/Dropbox/OneDrive** |
| **文件完整性校验** | `verify.rs` 只有 zip 的 EOCD 头部检查；**无通用 MD5/SHA1/SHA256 校验**，无法与网站公布的 hash 比对 | aria2（`--check-integrity`）、IDM/FDM 下载完成后校验并提示 |
| **HLS 转封装** | 只把 `.ts` 分片顺序拼接成 `.ts`；**不支持转 mp4/mp3**，且码率只能取最高（无法选低码率） | Downie/yt-dlp 及多数工具直接输出 mp4，并可按需选码率 |
| **API / RPC 远程管理** | 无本地 RPC 端口、无 REST/gRPC 接口、无 Web UI | aria2 的 JSON-RPC、JDownloader 的 API、FDM 的 API 可用于脚本/手机远程控制 |

### 4.3 P2 级 —— 锦上添花，与"全功能"仍有距离

| 缺失功能 | 现状 |
|---|---|
| **视频嗅探** | 无法从网页中自动探测页面内嵌的视频资源链接（IDM/Xtreamer 都有嗅探器，右键菜单直接出视频下载） |
| **BT 速率限制** | librqbit 会话参数里只有 peer 数/并发连接限制，**无上传/下载限速**，做种时可能打满上行 |
| **RSS / 站点监控** | 无 RSS 订阅、无目录/网站新文件监控自动下载（JDownloader/迅雷支持） |
| **脚本 / 插件扩展** | 无扩展机制（JDownloader 的 Python 脚本、IDM 的 API 均支持用户自定义处理） |
| **批量 / 站群下载** | 不能一次性下载整个网站/文件夹、不能从文本批量导入（IDM 可"下载整个站点"） |
| **下载后动作 / 通知** | 任务完成仅标记状态 + 写 `finished_at`，**无完成通知、无自动执行命令**（macOS 仅有 dock 图标） |
| **统计与历史** | 无下载历史数据库、无速度曲线、无流量统计 |
| **拖拽添加** | 界面仅有列表滚动拖拽，**不支持把文件/文件夹/链接直接拖入窗口**添加任务 |
| **二维码** | 无扫码输入链接/登录功能 |
| **网盘多账号** | 无账号管理界面，BDUSS 只能手动替换 |
| **自动更新** | 未知是否内置更新检查 |
| **密码保护** | 无 UI 打开密码 / 任务加密 |
| **上传 / 分享** | 仅下载，无任何上传能力 |

## 六、结论与优先级建议

**一句话总结**：QuickGet 的核心竞争力在"轻量跨平台 + 多连接 HTTP + BT 一体化 + 百度网盘"，它**不缺下载能力，缺的是下载器的"管理与自动化"能力**——限速、代理、下载规则、计划任务、网盘矩阵、API、嗅探这些让下载器从"能下"变成"好用"的中层功能基本空白。

### 若以"补齐短板"为方向，建议迭代顺序

1. **下载限速**（settings 加 `download_limit`/`upload_limit`，引擎限流）—— 最小改动、感知最强、对标 FDM/Motrix 的入门门槛。
2. **代理支持**（全局 HTTP/SOCKS5，reqwest 已有 socks feature）—— 与限速同为网络层配置，实现成本接近。
3. **下载规则**（URL 模式 → 目录/连接数/UA 自动匹配）—— 规则引擎是 IDM/FDM 的用户粘性来源。
4. **网盘矩阵**（按 `ShareProvider` 插件机制新增 阿里云盘/夸克/123 网盘/蓝奏云；JDownloader 式的插件注册表已存在，只需实现）—— 最贴合中文用户。
5. **计划任务 + 下载后动作**（定时、限速时段、完成通知/命令）—— 中后台能力。
6. **API/RPC**（内嵌轻量 JSON-RPC 服务）—— 自动化/远程控制的基础，aria2 已验证可行性。
7. **文件校验**（通用 SHA256 校验）—— 安全感需求，成本低。
8. **视频嗅探 / HLS 转封装** —— 面向影音场景，需引入解析逻辑或 ffmpeg 依赖。

### 若以"差异化竞争"为方向

QuickGet 的**原生无 Electron（内存/体积优势）+ GPUI 自绘界面 + Rust 多连接内核 + 百度网盘**是一条清晰路线。与其在"全功能"上与 JDownloader 正面对抗，不如把"轻量、快、无依赖"做到极致，并围绕"百度网盘一键下载"与"本地 BT 混用"打磨体验——这是它目前唯一明显领先于 FDM/Motrix 的领域。

### 一个需要澄清的点

- QuickGet 与 **quickemu/quickget** 是**同名不同物**的两个工具（后者是"下载 ISO + 生成 VM 配置"的 CLI）。用户若混淆，建议在发布物料中强化项目名称与图标区分。
